# 通知面板的消息规则与像素历史

范围为 macOS x86_64 UrW 3.89.1。下列地址来自 `build/disassembly.txt`，均为未加 ASLR slide 的虚拟地址。对应测试可执行文件 SHA-256 为 `124f89da263b7dabb323fd4f94718261abbe0ef76371a7e5ed5d6b50492ae112`。以下为静态分析与待验证的实现方案。

## 消息来源与模板

- `MSG(char*)` 在 `0x1001b50a0`。入口解析变量键并调用 `MSG_parse`（`0x1001b512c/134`），另有 `[]` 表达式读取与拼接分支（`0x1001b5194–523d`）。`MSG_parse` 在 `0x1001b8a60`，构造 `.%s.` 段落键，查询可变键（`0x1001b8ae7`），通过 `messages/%s_*.txt` 枚举资源（`0x1001b8bcb–8c91`）。`MSG` 最终返回 `_MESSAGE_s`（`0x1001b5413/5432`）。资源目录有 `urw_msg.txt`、`urw_combat.txt`、`urw_defs.txt` 等，段落、选项及变量表达式应保留来源信息。
- `CHATMSG(char*)` 在 `0x1001b9190`。它打开 `messages/%s_chat.txt`（`0x1001b9229–925c`），用 `.%s.` 找段落，识别多个态度分支（如 `(steal`、`(overall`），选定结果后调用变量解析（`0x1001b9659`）。例如 `0x100032673` 的调用者把返回值复制到自己的缓冲区。应按各调用者的最终展示位置归类，聊天面板和通知面板各有自己的绘制入口。
- `Note(char*)` 也接收调用者直接生成的字符串。空输入或 `DISABLE_NOTES` 提前返回。首字节为 `*` 时，`0x10012d121–12e` 把后续两个字节交给 `coded_st`。后者从 `_GAME_STRINGS` 查找编码条目并写入 `_NOTE`（`0x1001ba204–28a`），扫描步长为 `0x82` 字节。其他输入限长复制到清零后的 1024 字节 `_NOTE`（`0x10012d110–144`）。开头解析出的 `{...}` 存入本地音效键，正文从 `}` 后复制回 `_NOTE`（`0x10012d149–1a4`）。接着执行句首大小写规则并复位 `_NOTEMOD_alkuok`，用 `_lastnote` 和 `_NOTE_TUPLAOK` 处理重复（`0x10012d1a9–2af`）。
- 规则库宜以已展开的正文做展示匹配，并保留资源文件、段落、调用点或格式串作为采集证据。复用当前 `message` 精确项与锚定模板，分别处理原生控制符和可见正文，使用有类型的变量槽，歧义回退原文。通过多个真实实例确认变量边界。模板无法安全确定时记录未覆盖项。生产者返回值和原生共享缓冲区继续用于逻辑、去重、声音和日志。

## 前缀、换行和提交

`Note` 在 `0x10012d404–417` 用首字节查跳转表。表基址为 `0x10012d888`，索引为首字节减 `0x21`，元素为有符号 32 位相对偏移。从 Mach-O 文件读取该表得到以下非默认分支。RGB 值指传给 `RGB_to_color` 的参数。

| 前缀 | 地址 | 原生行为 |
| --- | --- | --- |
| `!` | `0x10012d419` | `COLOR_RED()` |
| `#` | `0x10012d49f` | RGB 20, 50, 112 |
| `&` | `0x10012d4c3` | RGB 102, 51, 51，尾字节为 `!` 时改用 204, 51, 51 |
| `+` | `0x10012d52c` | `COLOR_BROWN()` |
| `:` | `0x10012d53e` | RGB 60, 90, 152 |
| `<` | `0x10012d552` | RGB 176, 196, 222，保留可见的 `<` |
| `=` | `0x10012d575` | RGB 0, 128, 0 |
| `>` | `0x10012d5a2` | RGB 255, 255, 255 |
| `?` | `0x10012d5c8` | RGB 20, 120, 112 |
| `_` | `0x10012d5ee` | RGB 87, 87, 87 |

常规分支走 `0x10012d43e`，这里对 `@` 跳过可见输出（`0x10012d442`）。`_NOTE` 保留部分控制符，`showtext` 收到已处理的片段和实际像素色值。最好让原生分支定色并从调用参数继承颜色。目录归一化必须在确认首字节语义后才去掉控制符。

`Note` 先执行 `MoreCheck` 和 `note_bottom`（`0x10012d334/339`）。逐字节构造 `_AfterSpace`，在空格和最终片段分别检查 `notex + textwidth >= 0x318`（`0x10012d464–495`、`0x10012d62f–65e`），超出则按同样顺序分页、滚动。两个直接绘制调用点是 `0x10012d395` 和 `0x10012d691`。绘制后用原文宽度更新 `_notex`，并把最终位置写给 `_WhereXN/_WhereYN`（`0x10012d69e–6c0`）。这些坐标还用于 `KyllaE` 与 `KeskeytaKyllaE` 的确认回答 ` Yes`/` No`（`0x100132843–286c`、`0x100132a3b–2a64`），因此译文不能覆盖答案锚点。声音分支后由 `0x10012d6e7` 调用 `FlipWithMap`，随后在 `0x10012d73d` 调用 `logmsg`。

## 两种历史

- 实时通知在 `_screen` 上累积为像素。`note_bottom`（`0x10012cb20`）用 `_noteboxGui` 的四个连续 32 位坐标与尺寸，构造距离边框 5 px 的内区。从 `y + 5 + textlineh(1.0f)` 开始自拷贝至 `y + 5`（`0x10012cbd1`），并填充新露出的一行（背景 RGB 226, 197, 153，`0x10012cc46`）。`0x10012cc63/cc87` 写入新行原点。分页阈值为 `_lines > 9 + 5 * (_NEWHEADINGBRANCH != 0)`（`0x10012c6a0–6bf`）。打开原生分页并达到阈值时，`MoreCheck` 保存局部画面，显示继续提示并等待输入，再恢复局部画面（`0x10012c6db–c79c`）。因此下次原生滚动会直接搬走本次已写入的译文字形。
- `PlayerAction` 在 `0x1001d43fe–441f` 设置待淡化状态并清空后缀锚点。下一条 `Note` 的 `0x10012d768–87f` 对通知内区已有非背景像素应用按行变化的颜色。复用软件表面的译文字形也经过该路径。面板重置例子为 `StatScreen` 的 `0x100131083–1106`，该路径重画 `bg-rpanel.png` 和面板框并清锚点。`FlipWithMap`（`0x10014acd0`）调用 `RenderDoScreen`，后者在 `0x100149780–9790` 从 `_screen` 上传纹理，再由后续渲染与提交显示。
- 独立的 Message log 从 `CharacterPath/msglog.txt` 读写。`logmsg`（`0x10012ce50`）以追加模式写 RGB、四个日期相关编码字符、原始首字节、位置和可见文本，分隔符为 ` | `（`0x10012ce89–12d021`）。`MsgLog()`（`0x1001353f0`）打开文件读取记录并显示独立窗口，使用 `showtext_sanataulukko`（`0x10013593c`）。如需本地化该窗口，应在读取并解析记录后、布局前做展示替换，保留日志文件的原生内容。

## 重影原因与实现边界

现有 `captureNote` 先让原生函数滚动并提交画面，在 `prepareNote` 抑制被命中的字形，然后从原生最后一次 `showtext` 的 y 坐标向上按 CoreText 布局补画。它只在需要更多行时于返回后调用 `note_bottom`，最后再次调用 `FlipWithMap`。盒高检查只能证明译文可能装进整个面板。译文实际的占行数、字形像素边界、原生行距及这次滚动后已清出的行带需要分别核对。一旦译文画进旧行，后续滚动和上传会保留这些叠字。若第二次翻屏之前有原生分页，暂时被抑制的当前消息也可能缺字。这是已确认的机制与现象的对应解释，具体复现仍需截帧验证。

初版可保留游戏的行配额与分页。只拦截当前 `Note` 帧的两个已验证绘制调用点，使用原生颜色，按实际滚动得出的行带裁剪字形，预先验证译文能完整显示且给潜在确认后缀留位。应在该行下一次 `MoreCheck` 或最终 `FlipWithMap` 前完成落笔。若无法提前保证整条译文可提交，可先只覆盖能预判的单行消息，并保留完整原生路径作为回退。更一般的多行实现可暂存本行的原生绘制指令，在首个 `MoreCheck` 前提交经验证的译文或回放原文，避免回退时前几行已经滚走。遇到新的绘制路径或渲染失败时，要在任何画面提交前回退，防止混合半条译文。取消 post-return 补滚和重复提交。

如果译文要有独立行数，需把新行接入原生 `MoreCheck → note_bottom → draw` 顺序，并验证确认锚点与屏幕快照。另一种可验证的实现是维护有限、同一代面板内的行缓冲，在原生提交前完整擦写面板内区。采用行缓冲时需覆盖面板重置、淡化、确认后缀、暂停快照恢复、改尺寸及换角色的生命周期，避免从过期缓存重放历史。当前证据只支持原生软件表面保存了实时历史像素，尚未枚举所有存屏和恢复入口。

## 验收

1. 在隔离环境对比原版与补丁，覆盖连续短通知、原生换行、译文长于英文、译文短于英文、字体实际像素越界和没有匹配的消息。按帧检查每次提交的新行、老行的整数像素位移和相邻面板边框。
2. 制造一串超出可视历史的事件，走 Space/ESC 分页。保存分页前后、纯地图刷新后、进入和退出其他面板后的截图，核对旧行是否只滚动或淡化一次。
3. 覆盖重复消息、首字节颜色、`{...}` 音效键、编码消息 `*xy`、字面 `<`、动态人名和物名。验证声音、去重、原生日志内容与配置关闭时的表现。
4. 用确认弹窗分别选 Yes/No，检查后缀与译文互不覆盖，保留点击和键盘行为。独立 Message log 若启用展示翻译，则另验文件内容、分页以及滚动范围。

## 已落地状态（2026-11-05）

上述“现有 captureNote”描述的是修复前实现。本轮已采用保守单行方案：首次原生 showtext 时按原生颜色绘制完整译文，后续分词绘制被抑制；note_bottom 纯透传，captureNote 返回后不再补滚或翻屏。字形垂直限制在 textlineh(1) 行带，水平不缩字；宽度上限同时受通知内框和原文保守宽度约束。含换行、未解析标签或超宽译文回退原文。

这不解决独立中文多行配额，原文换行时可能留下空行。138 条新规则只有在完整译文满足绘制边界时才显示，匹配日志不能代替绘制验收。单条拾取失败提示及 F2/Esc 往返已实测，其余验收项继续保留。

## 淡化像素规则与碎片回退修复

实机连续通知表明，抗锯齿浅边会在淡化后变成粗块。Note 的 0x10012d865 比较像素是否精确等于背景，0x10012d86f–0x10012d87a 将其他像素写为该行的实色淡化色；它不保留覆盖度。因此 drawNoteRow 对缩小后的 alpha 使用 128 阈值，输出只有原生颜色或透明的像素，通知以外的 UI 仍用抗锯齿。代价是低分辨率中文有断笔，字形清晰度仍待改善。

show 在 activeNote 存在时只允许 prepareNote 的整句结果，回退则调用原版而不再进入通用 showtext 词条。否则诸如 You、wielded 的独立命中会混入未翻译通知。地面多对象的逐项 Note 仍需按 Display_Items 调用点专门启用物品组合器；没有将所有短消息无条件当物品名处理。

## 移动、观察和物品通知补充

`notifications_followup.json` 的完整消息取自实机捕获和直接调用 `Note` 的二进制字面量，覆盖缩放、涉水、冰面、滑雪、拖运、丢弃和部分采集操作。所有完整通知使用 `message` 上下文。植物名称和时长短语分别存放在独立上下文，只能用于下列整句。

- 观察函数在 `0x10013df94/0x10013dfff` 使用 `#You see %s %s.`。植物描述在 `0x100007ed1/0x100007ed8` 选择 `FLORA_INFO_SINGLE` 或 `FLORA_INFO_PATCH`。`messages/urw_defs.txt` 定义单株、复数、成片和三个阶段词。植物名称来自已审校的浆果、作物和草本条目，保留数值并匹配完整名称。
- `KASVIDATA_harvestinfo` 使用 `HARVEST_FLOWERING_TIME`、`HARVEST_TIME` 和 `WITHER_TIME`（`0x10000733d/0x10000734f/0x1000073d6`）。译文只接收 `TIMESPAN_DAY` 定义的展开值，分别显示预计开花、成熟和枯死的时间。
- 拾取、放下、卸下、清空容器、采收和收割匹配资源中的完整通知，复用物品名和物品列表规则。观察人物与让路通知复用人物身份规则，保留原有人名。技能通知在 `0x1001680e5` 使用 `#Using: `，只接受 `ini_skills.txt` 的技能名。武器鉴定使用 `EXAMINE_ITEM_SKILL` 和 `EXAMINE_ITEM_CLASS`（`0x100057d51/0x100057d7d`），加成幅度限定为 `urw_combat.txt` 中 `WEAPON_CLASS` 的七个值。

## 缩放与追踪

`Note` 直接接收 `#Zooming in ...` 和 `#Zooming out ...`（`0x10003a929/0x10003ab5c`）。进入局部地图时，`0x100039304–0x1000393bd` 用 `terrain_desc` 的小写结果生成 `There is %s here and ...`，结尾分为仔细察看和遭遇。译文查找现有地形词表，保留整句边界。

`Tutki_Datajaljet` 在 `0x1001c0f06` 格式化足迹说明，时效在九个固定短语中选择。随后拼接八方之一，或描述足迹交错、混有模糊痕迹。译文分别审查时效、足迹主体、步态和结尾，任一部分未识别时保留原文。方向用现有八方表。
