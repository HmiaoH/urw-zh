# 角色档案、护甲与人物查看

以下位置对应 macOS 3.89.1 的受支持二进制。翻译表为 `data/translations/profile_armor_look.json`。

- `draw_profile` 生成开局、首日、已过一天、已过多天四种年龄文字。属性经 `desced_stat` 先画标签，再用矩形画数值条。身高和体重经 `TekstiPalkki` 绘制，使用返回地址 `0x100116c93`、`0x100116cfc` 限定单位模板，数值和游戏单位制保持原样。
- `armour_screen` 将防护说明分成六行绘制，三个图例各占一行。`armour_coverage` 创建钝击、刺击、挤压、斩切、撕扯、保暖和平均七个按钮。按钮函数逐个绘制字符，运行时保留彩色快捷键和原生按钮几何，仅在快捷键之后的字宽内绘制类别中文。身体图由贴图和 19 个填色区域组成，部位译名依据原生 `bodypart` 表。
- `NPC_inforuutu` 先放入身份，再加入由 `NPC_IS_WEARING`、`NPC_IS_CARRYING` 生成的列表。着装走七个槽位，使用 `ekuvaus` 取完整显示名，再由 `SANATAULUKKO_Pilkkulistaus` 组成逗号列表。解析器要求身份的部族和称谓均在白名单中，物品也必须逐件匹配 `composeItem`。它保留 `<blue>`、`<black>`、`<red>` 和 `<br>` 的顺序，遇到未知描述或物品则保留原段落。

测试覆盖了捕获中的库伊卡女孩与两件衣物、保留人名、部族与职业组合、含三个物品的列表、持械描述和未知词回退。

## 原生弹窗测量与提交

`NPC_inforuutu` 在返回点 0x1000cf788 以 280 像素宽度测量段落，在 0x1000cf855 用相同宽度绘制。窗口高度为测量值加 35，正文从窗口 y+30 开始。因此测量必须返回完整段落高度，而不是最后一行起点；前者保留末行及 5 像素边距。此调整仅限该测量调用点，不修改其他段落的游标返回约定。

地图在软件窗口之后渲染，随后 0x1000cf902 调用 FlipScreenPortion 恢复弹窗。专用分支保留原生纹理内容、视口、混合与裁剪状态，显式提交弹窗源/目标矩形。用户截图已证实恢复主体覆盖关系；高度补偿需独立复验，不把这两种缺陷混为一项。
